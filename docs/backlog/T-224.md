# T-224 — Retire the dead tag-writing plugins (beets kept as the import framework)

> **Wave 4 (final) of epic [`T-220`](T-220.md) · needs T-221–T-223.** Base: **ADR-033** (ratified
> 2026-08-26, **amended 2026-08-27** — this ticket). **DONE 2026-08-27.**

## Re-scope (2026-08-27)

The ticket was written to "remove beets itself from the dependency set." Building it established that
premise was wrong: **beets is not the tagger — it is the import framework.** `FingerprintTrustSession`
**is** a beets `ImportSession`, and beets still owns candidate generation (`chroma` → recordings),
MusicBrainz hydration, the file organize (path template + NTFS/WSL sanitizer + `%aunique`), and the
library DB that ADR-009 dedup queries. Tag-writing — the thing T-221–T-223 already moved to Shazam +
mutagen — was only a quarter of what beets does. Removing the rest is a bounded-but-multi-day spine
rewrite whose payoff is dead-weight removal, not a user-facing win (speed + correct covers already
shipped; none of the retired plugins even call MusicBrainz). Three research agents confirmed each job
is replaceable but welded into the one `ImportSession` object graph — all-or-nothing.

So T-224 was re-scoped (owner-approved) to the **safe, shippable subtraction** — retire the four
now-dead tag plugins — and **full beets removal is deferred to its own sub-wave, [`T-226`](T-226.md).**
ADR-033 decision 3 amended accordingly.

## Scope (as built)

- Drop `lastgenre`, `fetchart`, `embedart`, `lyrics` from `PLUGINS` (`app/beets_engine.py`). Keep
  `musicbrainz` (candidate hydration), `chroma` (fingerprint candidates), `ftintitle` (feat. fold).
- Trim `requirements.txt` to `beets[chroma]==2.12.0`; **pin `Pillow` directly** (it had ridden in via
  the `embedart` extra; `app/artwork.py` uses it for crop/validation). pylast / beautifulsoup4 /
  langdetect drop out with the extras — confirmed unreferenced by app code.
- Wire the Shazam record's **lyrics** through the mutagen writer (`_apply_shazam_tags`, renamed from
  `_apply_shazam_year_genre`): lyrics used to come from the `lyrics` plugin, so dropping it without this
  would silently regress lyrics. ADR-033 decision 4 ("lyrics best-effort when clean; no lyrics-plugin
  fetch") is now satisfied by the Shazam source. An AcoustID-only land gets no lyrics (Shazam missed).
- Drop the Last.fm key wiring (`plugins.LASTFM_KEY`) and the dead `config["lyrics"]` tuning. The
  `lastfm_apikey` setting is **retained but inert** (kept so an existing `.env` still loads; a docs pass
  can retire the spec §6 / `.env.example` references).
- Delete the now-dead `artwork.embed_cover` (beets `embedart` helper — the land path uses the mutagen
  APIC writer since T-223) and its round-trip tests.

## Not / deferred

- **Lyrics quality trade (owner, note):** the retired `lyrics` plugin fetched *synced* LRC (SYLT) from
  LRCLib so Jellyfin could scroll lyrics with playback; Shazam's LYRICS section is *plain* lines, written to
  a plain USLT frame. So landed tracks keep lyrics but lose the scrolling/synced view. Inherent to "use what
  Shazam gives us free" (ADR-033 decision 4); richer/synced lyrics belong to the R2.5 polish pass.
- **Full beets removal → [`T-226`](T-226.md)** (its own sub-wave): AcoustID rescue sense → the `acoustid`
  library; AcoustID-only `get_recording` → `musicbrainzngs`; the mover (organize + sanitizer + `%aunique`)
  → plain Python; the memory (ADR-009 dedup) → a recording-id tag stamped by the writer + a library scan;
  then retire the `ImportSession` spine and drop the dependency. The **dedup + path-sanitization
  carry-forward trap** the original T-224 flagged lives there, not here (this ticket does not touch them).
- **The live 16-track compare** (epic acceptance bar) is not load-bearing for *this* scope: identification
  is untouched, so outcomes cannot move; the tag/art behaviour is covered by the real-mutagen on-disk seam
  tests. It remains the acceptance gate for T-226, where the engine actually changes.
