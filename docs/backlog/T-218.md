## MEASURED (2026-08-23) — the real per-sub-step split

Instrumented harness (scratchpad `measure_identify.py`, **nothing committed to the engine**): fully
isolated `DB_PATH` + patched `LIBRARY_DIRECTORY`, drives `download → transcode → import_song` directly.
Timers wrap the three injectable senses (AcoustID `dominance_fn`, `shazam_fn`, LLM `reconcile_fn`) and
`MusicBrainzAPI._get_resource` (every MB fetch, 1/sec rate sleep included). Real library confirmed
untouched (nothing in `…/Music/CleanMuzik` in the run window; the auto-land went to the temp library).

Four runs — the parking fixture (Nines "Franklin", parks) ×3 and a clean-landing track (Rick Astley
`dQw4w9WgXcQ`, auto-lands) — gate (`import_song`) totals and sub-steps, seconds:

| Run | Gate | **MB (n calls)** | AcoustID | Shazam(+ISRC) | LLM | remainder |
|-----|-----:|-----:|-----:|-----:|-----:|-----:|
| Park 1 | 88.2 | **79.6 (6)** | 0.80 | 2.32 | 3.91 | 1.5 |
| Park 2 | 24.4 | **16.5 (6)** | 0.62 | 2.17 | 3.60 | 1.5 |
| Park 3 | 13.2 | **6.2 (6)** | 0.62 | 1.67 | 3.34 | 1.4 |
| Land (NGGYU) | 29.6 | **23.7 (11)** | 1.26 | 1.63+0.46 | 3.33 | ~0¹ |

¹ tiny negative remainder = the ISRC→MB call is double-counted (in both `isrc` and `mb_net`); immaterial.

**Findings.**
1. **MB is the fattest slice in every run — 80–90% of the gate.** Nothing else is close.
2. **MB is the *entire* variance.** AcoustID (~0.6–1.3s), Shazam (~1.7–2.3s), LLM (~3.3–3.9s) and the
   post-choose remainder (~1.5s) are rock-stable — a combined **~6–8s floor**. The 28s prior number was
   a lucky MB day; 88s is an unlucky one. Same code, MB latency alone swings the total 13s→88s.
3. **MB has a catastrophic per-call tail** — individual `_get_resource` calls hit 21s and 34s (park 1),
   11s (land). Serialized behind the 1/sec limiter, `n` calls stack.
4. **The fan-out is real and mostly wasted.** `n` scales with candidate count (6 park → **11** land).
   The killer: the landing track **auto-landed on a dominant fingerprint** yet still made 11 serialized
   MB round-trips hydrating candidates it then discarded. The fingerprint already picked the winner.
5. **Every MB call is identity hydration — `recording/<mbid>` (endpoint-classified 2026-08-23).** On the
   land track: **10× `recording/<id>` + 1× `recording` search; zero `release/`, zero ISRC album lookups.**
   And it **re-hydrates the same recording** — `8f3471b5`, `a45eb41b`, `1cc4720e` each fetched twice, no
   session cache. This is **beets using MB as its identity-candidate mechanism**, feeding a decision the
   AcoustID fingerprint + Shazam + LLM gate has largely already made.

### Contrast with muziktest (owner note, 2026-08-23)
In the **muziktest** clean-room rewrite, MB has *nothing to do with identity* (that's AcoustID+Shazam+LLM).
MB is consulted **only for the album tag**, in a gated 3-tier `_album_waterfall`: Tier 0 = Shazam's own
album (stop if it's a real studio album — MB never runs); Tier 1 = **one** MB lookup *by ISRC*, only if
Shazam's album is non-canonical/missing; Tier 2 = AI. Artist/title always from Shazam. Net MB cost ≈ 0.
**cleanmuzik's ~10-call recording fan-out is a beets-architecture artifact, not an inherent cost of MB.**

## Verdict — the target is the MB *recording* fan-out (two levers, one target)

The fattest slice is the beets MB recording-hydration fan-out. Two ways to cut it, small→large:

- **Lever A — T-208, within beets (ADR-005-safe). ← OWNER CHOSE THIS (2026-08-23).** Stop hydrating
  every fingerprint candidate: on a **confident match hydrate only the winner** (~10 → 1); on a **weak
  match hydrate the top 3** and park to review (re-search stays the fallback); and **de-dupe** repeat
  MBIDs within a session. Removes the bulk of both median cost and the tail without leaving the beets
  engine. Engine-touching → R2.5-gated. Full design in [`T-208`](T-208.md).
- **Lever B — adopt the muziktest model (needs an ADR).** Take MB out of identity entirely (AcoustID +
  Shazam + LLM already decide it) and reduce MB to the gated album-only `_album_waterfall` (Tier-1 ISRC
  lookup, usually skipped). Near-zero MB cost. **But it reworks the identity path and rubs against
  ADR-005 (beets-not-hand-rolled)** — an owner/ADR decision, not a backlog build. The muziktest repo is
  where that architecture already lives.
- **T-215 (run Shazam during the MB search) is refuted.** Shazam is ~2s; overlapping it saves at most
  ~2s against a 10–80s MB block. Not worth the engine risk.
- **LLM (~3.5s) is stable and cheap** — not a target; leave the accuracy vote alone.
- **Orthogonal cheap lever — a per-call MB timeout/cap** would tame the 18–34s tail regardless of A/B.
  Natural home: **T-210** (shared MB rate limiter).
- **Constraint to respect:** the ADRs forbid parallelizing *across tracks* (batch stays sequential);
  overlapping sub-steps *within one track* (what T-215 does) is allowed.
