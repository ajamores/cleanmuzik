# T-226 — Remove beets entirely (replace the import framework)

> **Backlog · sub-wave · NOT SCHEDULED.** Filed 2026-08-27 from the T-224 re-scope (see
> [`T-224`](T-224.md) + the ADR-033 amendment, 2026-08-27). This is the "throw the knife away" job the
> original T-224 assumed was a plugin-list edit; it is a bounded-but-multi-day spine rewrite. Do it as its
> own deliberate release-piece, not the tail of an epic. **Owner decision to schedule.**

## Why this is separate from T-224

T-224 retired the four tag-writing plugins (`lastgenre`/`fetchart`/`embedart`/`lyrics`) — the part beets
was no longer doing. What remains is beets as the **import framework**: `FingerprintTrustSession` **is** a
beets `ImportSession`. Removing the dependency means replacing four welded jobs at once (they share the
one `ImportSession` object graph — none can be excised alone). The payoff is engineering hygiene (no heavy
dead dependency), **not** a user-facing win: the epic's speed + correct-cover gains already shipped in
T-221–223, and none of beets' remaining work is on a hot MusicBrainz path.

## The four jobs and their replacements (from the 2026-08-27 research)

1. **Mover** — organize into `$artist/$title.mp3`, sanitize NTFS/WSL illegal chars, collision suffix.
   **Verdict: replaceable-cheaply (~50 lines).** Only the `singleton` template ever fires (`%aunique` is
   dead on this path). Must reproduce: the 6-rule char sanitizer, NFC normalization, 200-**byte** (not
   char) component truncation, and the `.N`-on-collision copy (`util.unique_path` — the real disambiguator,
   not `%aunique`). Miss NFC → the NTFS `NOT_INDEXED` mount mismatch returns.
2. **Memory** — ADR-009 non-destructive dedup, one `MatchQuery("mb_trackid", …)` against the beets library
   DB. **Verdict: replaceable-with-effort, GATED on a writer change:** the mutagen writer does **not**
   currently stamp the recording id onto the file, so first add a `UFID`/`TXXX` recording-id frame in
   `tagwriter.write_tags` (the id is already in hand at `_accept`). Then dedup = walk `LIBRARY_DIRECTORY`,
   read that frame via `mediafile`, match. Scan-on-demand beats a maintained SQLite index at single-user
   scale (self-healing vs. the migrate/clean flow). `_replace_existing` must move from beets `item.id` to
   path identity. Backfill caveat: pre-change files carry no id frame (already the "untagged legacy = R2
   migrate input" case).
3. **Suggester** — candidate generation. **Verdict: replaceable-with-effort (medium).** The recording
   MBIDs are already free: `_lookup_dominance` extracts `recording_ids` from the same AcoustID response
   `chroma` parses. Build our own `Candidate` dataclass from them; drop `chroma`. Costs: reproduce (or
   simplify) beets' `track_distance` scorer (park-row scores + reconcile discrimination re-tune to ADR-020/
   T-028), and replace the `TrackMatch`/`TrackInfo`/`Distance`/`Recommendation` types (small — ~9 fields
   ever read, ~5 app files + ~3 test files).
4. **Hydration + driver** — `get_recording` / `track_for_id` and the `ImportSession` spine. Move MB
   hydration to `musicbrainzngs` (not currently a dep) or extend `app/isrc.py`'s proven direct-HTTP MB
   pattern. **Must build ONE shared 1-req/s MB limiter + bounded retry** across isrc + hydration + search
   (today `isrc.py` and beets keep separate limiters — the deferred T-210 correctness half). Then the
   `ImportSession` subclass collapses to a plain driver function once mover + suggester no longer ride it.

## Sequencing (each its own ticket + the ADR-030/032 compare bar)

1. Writer stamps the recording-id frame + library-scan dedup replaces the beets DB.
2. Plain-Python mover replaces beets organize (+ the NTFS sanitizer).
3. Own candidate dataclasses + direct-HTTP/`musicbrainzngs` hydration + shared MB limiter; drop `chroma`.
4. Retire the `ImportSession` driver; drop `beets` + `mediafile`-via-beets from deps.
