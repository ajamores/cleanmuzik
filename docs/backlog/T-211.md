# T-211 — Harden the loose name-matcher against short-name substring false-positives

**Status:** untriaged
**Found:** 2026-08-11 (T-205 code-review, PLAUSIBLE finding — high-effort workflow review)

## Problem

`normalize.loose_match` (the T-205 sense-support comparison) matches on **substring
containment**: either alnum-folded name contained in the other counts as a match. That is
the owner-ratified behaviour (2026-08-10) — it forgives YouTube's appended cruft
(`"Pa Salieu"` ⊂ `"Pa Salieu (Official Video)"`), and the ratification rested on "a lone
loose match auto-lands nothing; the 2-of-3 rule covers the short-name false-match risk."

That rationale has a hole for **correlated** errors. Because containment matches a substring
*anywhere*, `"Sia"` ⊂ `"Asia"`. If the YouTube sense and the Shazam sense **both**
coincidentally point at the same wrong candidate — each a substring artifact on artist AND
title — `_agreeing_senses` re-derives 2 genuine agreements and the gate **auto-lands the
wrong recording with no review**. This is the system's worst failure mode (a silent
mis-file), reached without any single sense being individually at fault.

## Why deferred, not fixed in T-205

- **Risk is low.** It needs two independent senses to make the *same* substring mistake on
  *both* artist and title, plus the AI to accept it — a stack of correlated coincidences.
  Not observed in the exp-9 corpus (all ASCII, no short-name collisions).
- **The obvious fixes don't work.** Prefix/suffix matching still admits it —
  `"asia".endswith("sia")`. A real fix is a **token/word-boundary-aware** matcher: whole
  words must align (`"sia"` is not a whole word inside `"asia"`, but `"pa salieu"` is a whole
  run inside `"pa salieu official video"`). That is genuine design work with its own tests.
- **It reverses a ratified decision.** Containment-over-equality was owner-ratified; changing
  the matcher semantics is an ADR-level move, not an incidental hardening.

## Done when

`loose_match` rejects mid-word substring collisions (`"Sia"` ≠ `"Asia"`) while still
forgiving whole-word cruft (`"Pa Salieu"` ≈ `"Pa Salieu (Official Video)"`), the two §7
acceptance cases still hold (Pa Salieu lands, Strawberry Swing parks), and the change is
recorded as an amendment to the 2026-08-10 normalizer ratification. Graduate this if the
T-209 verify sweep surfaces any short-name mis-land, or sooner if the library grows enough
to make the collision non-hypothetical.
