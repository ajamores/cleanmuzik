# T-400 — `.m3u8` playlist file beside the tracks (server-agnostic playlists)

> **Backlog (untriaged).** Filed 2026-08-23. From the Navidrome pivot: the owner is adopting
> **Navidrome + Symfonium/Feishin** as the listening/car layer while keeping CleanMuzik as the
> acquire/tag engine. Navidrome reads playlists as `.m3u`/`.m3u8` files **on disk**, not from an API —
> so R2's Jellyfin-DB playlists are invisible to it. This ticket writes the disk-side playlist so the
> library becomes **server-agnostic**. Part of the **T-40x listening-layer** set; graduates when R3
> (or a "listening layer" release) moves to `specing`.

- **Status:** todo — untriaged. Phased plan option 1 (keep Jellyfin *and* add Navidrome).
- **The gap.** R2 mirrors a YouTube playlist into a **Jellyfin** playlist via the Jellyfin API
  (`server/app/jellyfin.py`, the `resolve_item_id` / playlist-append path — the layer T-316's path bug
  lived in). Navidrome never sees it. Albums/artists/tracks show up in Navidrome from the embedded tags
  for free; **playlists do not** until we drop an `.m3u8` beside the files.
- **Prior art — port, don't reinvent.** The sibling rewrite `~/github/muziktest` already solved this:
  **ADR-0005** (`docs/adr/0005-playlist-grouping-as-a-merged-m3u8.md`) + `src/muzik/real/playlist.py`.
  Key design decisions to carry over:
  - One `.m3u8` per playlist, named after the playlist's **yt-dlp title** (filesystem-sanitized), written
    in the library/output dir. Extended-M3U: `#EXTM3U`, then `#EXTINF:<seconds>,<Artist> - <Title>` + a
    **relative, forward-slash** path per landed track (portable, survives a folder move).
  - **Merge across re-runs** (the hard part): a re-paste of a grown playlist only sees freshly-fetched
    tracks (the download archive skips the rest), so a naive rewrite would drop the earlier ones. Read the
    prior `.m3u8`, keep entries whose file still exists (self-heals dead pointers), append the new tracks,
    overwrite-to-latest. **No versioned `List (2).m3u8`.**
  - Grouping lives **beside** the tags, never in them — a track's `album` tag stays its real album; one
    track can appear in two monthly lists with **one file on disk** (folder-grouping can't do that cleanly).
- **The shape of a fix (CleanMuzik side, undecided in detail).**
  - A playlist-writer seam the batch pipeline drives after tracks land (CleanMuzik's batch model already
    has ordered results per source). Keep it **additive** to the Jellyfin path for now (phased) — both
    fire; T-404 decides later whether Jellyfin's playlist code retires.
  - Decide where the `.m3u8` lands relative to `LIBRARY_DIRECTORY` and that Navidrome's
    `ND_PLAYLISTSPATH` / auto-import picks it up (Navidrome auto-imports `.m3u`/`.m3u8` from the library).
  - Reconcile with **ADR-027** (batch model) and the R2 playlist tickets (T-300s) — this is a second
    output target for the same batch, not a new batch concept.
- **Related:** R2 playlist tickets (T-300 series, shipped) · **T-316** (the Jellyfin path bug this
  approach sidesteps — Navidrome resolves from disk) · **T-401** (Navidrome standup that consumes this) ·
  **T-404** (verdict on Jellyfin). Prior art: `~/github/muziktest` ADR-0005.
- **Done when:** a playlist run writes a valid merged `.m3u8` beside the landed tracks; re-running a grown
  playlist preserves earlier tracks and adds new ones with no dead pointers; Navidrome imports it as a
  real playlist visible in Symfonium; the tracks' own tags are untouched; the existing Jellyfin playlist
  path still works (phased — nothing removed yet).
