# T-044 — Near-duplicate artist-folder tripwire (the "next mojibake class" alarm)

> **Backlog (untriaged).** Filed 2026-08-15 as the recorded follow-on to **ADR-028** (T-301). The
> Maintainability lens on the ADR-028 council raised it; the chair recorded it as a follow-on ticket,
> **explicitly not binding on T-308**.

- **Status:** todo — untriaged.
- **The gap.** ADR-028 fixes the *known* artist-credit split classes surgically: the enumerated
  confusable map (today only `Ÿ`→`Y`) plus the hyphen-class fold. By design it grows **one diagnosed pair
  at a time** — so the *next* mojibake/confusable class the map doesn't yet know about lands a fresh
  split **exactly as silently as T-037 did**, invisible until the owner notices two folders for one
  artist. ADR-028 closes Jay-Z; it does not make the *next* case loud.
- **The shape of a fix (undecided).** A tripwire that, when a landing creates a **new** artist folder,
  flags it if the name is a confusable/near-duplicate of an **existing** folder that the ADR-028 map did
  **not** repair — surfacing it to the owner (a review-inbox notice or a log/alert) rather than letting
  it split silently. Detection only — it does **not** auto-merge (that stays the owner's call, per the
  non-destructive posture of ADR-009). Open questions: where it lives (import tail vs. a periodic library
  scan), what "near-duplicate" means precisely (NFC-equal-but-not-byte-equal, single-confusable-apart,
  edit-distance), and how it surfaces without nagging on legitimately-distinct similar names.
- **Done when:** a fresh landing whose artist folder is a near-duplicate of an existing one **the map
  did not fold** is surfaced to the owner (not silently split), with no false alarm on two genuinely
  distinct similar artist names.
