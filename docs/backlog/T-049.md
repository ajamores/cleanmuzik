- **Status:** todo (backlog — not R2 scope; captured per the scope guard).

## The gap

T-308 folds ADR-028's enumerated credit fields — `artist`, `albumartist`, and their `_credit`
variants (`import_seam.py:_CREDIT_FIELDS`). Two other identity-bearing fields on the matched
`TrackInfo` are **not** folded:

- **`artist_sort` / `albumartist_sort`** — the ID3 sort frames (TSOP/TSO2). A match whose sort name
  carried the confusable/Unicode-hyphen would land with a folded *display* artist but a stylised
  *sort* value.
- **The plural `artists` list** — `item_data` carries an `artists: [...]` list for multi-artist
  credits. For a **solo** credit it is *derived from* the (now-folded) `artist`, so it is already
  clean; an explicit multi-artist list is independent and would keep a stylised element.

## Why it's not an active split today (why T-308 is complete without it)

- The **folder** is `$artist` / `$albumartist` (path formats, `beets_engine.PATHS`) — both folded, so
  the on-disk split (the T-037 symptom, T-308's Done-when) is closed.
- **Jellyfin groups its artist view by the artist *name* tag, not the sort name.** A stylised sort
  value mis-*orders* the single artist; it does not create a second artist entry.
- The `artists` list only matters for a genuinely **multi-artist** credit, and today's confusable map
  is exactly one pair (`Ÿ`→`Y`) for a **solo** artist (Jay-Z). No live case trips the list.

So the gap is latent: it would first bite a future song credited to several artists where one of them
carries a diagnosed confusable — none exists in the map today.

## What this ticket would build

- Add `artist_sort` / `albumartist_sort` to the folded field set (same pure `canonical_credit` fold —
  clean values pass byte-for-byte, so it is a no-op except on a stylised sort name).
- Fold the elements of the plural `artists` list (a **list**, so it needs list handling, not the
  current `isinstance(before, str)` string path — a small but real code change).
- Record the widened field set as an **ADR-028 addendum** (the enumeration deliberately grows one
  diagnosed need at a time; this is such a step, not a heuristic).

## Why filed, not fixed now

T-308's Done-when (a fresh matched credit lands under the single canonical folder) is met and proven
(`tests/test_credit_normalisation.py`). Widening the fold amends a council-ratified ADR (ADR-028's
field enumeration was deliberate) and adds list-handling for a case the current one-pair map cannot
reach — best taken as its own triaged step, per the owner's call, rather than folded into T-308.
