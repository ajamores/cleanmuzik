# T-042 — Loudness normalization: write ReplayGain tags at import

**Status:** untriaged
**Found:** 2026-08-05 (owner: "downloaded songs sound quieter than the YouTube versions")

## Problem

Landed tracks play back quieter — and at inconsistent levels track-to-track — compared to
the same songs on YouTube. This is **not** a pipeline bug: the transcode is a faithful MP3
320 CBR re-encode with **no loudness processing** (`app/transcode.py` — no `loudnorm`, no
`volume` filter), and beets loads **no `replaygain` plugin** (`app/beets_engine.py` PLUGINS:
`chroma embedart fetchart ftintitle lastgenre lyrics musicbrainz`). So each file lands at its
own master's native loudness.

The difference is YouTube: its player levels every track toward ~−14 LUFS **at playback
time**. yt-dlp downloads the raw upload, so that leveling is absent. YouTube was hiding the
master-to-master variance; the library shows it honestly.

**Deliberate, for now:** ADR-002 fixes the output *format* (MP3 320), not the *level*. The
project does no in-house loudness normalization by design — leveling is **delegated to
Jellyfin** (owner decision, 2026-08-05). On the owner's server (Jellyfin 10.11.11), `Enable
LUFS scan` (server-side measurement) + client **Audio Normalization → Track Gain** resolves
the listening experience with no code change. This ticket is the *portable* alternative, not
a fix for a broken flow.

## What option 2 would add

The beets `replaygain` plugin analyses each track at import and writes **ReplayGain 2.0 tags**
(`REPLAYGAIN_TRACK_GAIN` / `_PEAK`, `REPLAYGAIN_ALBUM_GAIN` / `_PEAK`) into the MP3. Any
player that reads them — Jellyfin included — levels on playback without re-measuring. The
audio bytes are untouched (tag-only mode, the default; **not** `mp3gain`-style apply), so it
composes cleanly with ADR-002's faithful-320 contract.

Advantage over the current Jellyfin-only approach: the gain is **portable** (travels with the
file to a phone, another player, a backup, or off Jellyfin entirely) and is stamped **once at
acquire time** rather than re-derived per server. If the owner only ever listens through this
Jellyfin, this is redundant with the LUFS-scan path already in place.

## Open decisions (needs a short ADR before building)

- **Target reference level** — ReplayGain 2.0 convention is −18 LUFS; confirm or override.
- **Track vs album default**, and whether single-song acquire (no album context) even has a
  meaningful album gain.
- **Backend** — beets' default is now the ffmpeg backend (no extra system tool), which fits.
- **Import-time cost** — an extra loudness-analysis pass per track; measure it's acceptable
  against the sequential-pipeline constraint (ADR-001).

## Done when

Landed MP3s carry valid ReplayGain 2.0 tags written at import, the audio bytes are unchanged
(verified byte-identical to a no-plugin transcode), and a ReplayGain-aware player levels them
on playback — proven end-to-end with the tag values read back off a landed file.
