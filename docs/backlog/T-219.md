# T-219 — Corroboration fast-path: skip the LLM reconcile when the fingerprint already agrees

**Status:** **DONE — integrated to `main` 2026-08-25 (ADR-032), 756 green.** Filed 2026-08-24 from the
muziktest head-to-head. A steady-cost speed lever, secondary to [`T-210`](T-210.md) (the MB tail is the
bigger remaining cost) but additive. Continues the T-21x speed series.

**Acceptance compare passed** (16-track live corpus, ADR-030 bar; harness `t219_compare.py` — `build`/`run`/
`control`, isolated temp libraries): **~20% faster on fast-pathed tracks (5.4s/track saved)**, 9/16 tracks
skipped the LLM. **Outcome-neutral** — the 3 land/park flips are MusicBrainz-503 noise, sitting at the same
floor a same-code `control` run (new engine twice) produced on its own (2/16, *different* tracks). The
smoking gun: the *old* engine parked a track its own LLM called "the definitive match" — a hydration 503,
not the fast-path. Report artifact + the raw `t219_results.json` hold the per-track table.

## What shipped

`FingerprintTrustSession._corroboration_fast_path` (`server/app/import_seam.py`), run in `choose_item`
*before* `_reconcile`: a dominant fingerprint whose recording is a beets candidate (`fp`) **and** whose
artist+title the YouTube source corroborates (`yt`, `normalize.loose_match`) lands through the shared
`_accept` tail with **no Shazam / ISRC / LLM call**. Everything weaker falls through to the full 2-of-3
gate unchanged — the fast-path is additive (only ever *skips* the LLM on a strong+corroborated match; a
`None` return falls straight through). Full rationale, the safety argument (fp+yt = the 2-of-3 bar
re-derived in code), and the two accepted behavioural changes (loss of the LLM's veto/override on the
corroborated path) are in **ADR-032**. Tests: `test_fast_path_dominant_fp_and_yt_agree_lands_without_llm`
+ four `test_fast_path_falls_through_*` in `server/tests/test_import_seam.py` (755 green).

**Compare outcome:** land/park + tags held identical between engines except for MB-503-driven flips (present
in the same-code control too, so not attributable to T-219); every fast-pathed track that landed did so with
its artwork + tags intact. No remaster-vs-ISRC-original recording shift surfaced in this corpus. Integrated.

## The idea (transplanted from muziktest's Confidence gate)

cleanmuzik calls the LLM `reconcile_fn` on **every** track (~3–6s each). muziktest doesn't: its Confidence
gate takes a **corroborated fast path** — when the fingerprint's identity already agrees with the Source's
own title, it auto-verifies with **no AI call**. On the shared 14-track playlist that fast-pathed **8 of 12
matched tracks**; the LLM ran only twice.

Port the same gate to cleanmuzik: when the dominant AcoustID fingerprint's recording **and** its
artist/title corroborate the YouTube-derived title (the `source_signals`), auto-land on the fingerprint
**without** invoking the reconcile LLM. Fall through to the existing 2-of-3 reconcile gate only when the
fingerprint is weak or the title doesn't corroborate — exactly the cases the LLM exists to adjudicate.

## Why it's worth it (and its size)

- After T-208, the LLM is part of the steady ~15s non-MB floor (T-218: ~3.5s/call, rock-stable). Removing
  it from the corroborated majority is a real per-track win on the common path.
- **Not the biggest lever** — the MB *latency tail* (T-210) is #1. This is the next steady rock, not the
  boulder. Do T-210 first.

## Guardrails (do not weaken the safety spine)

- The fast-path is **additive**: it only ever *skips* the LLM on a strong+corroborated match. Every weak or
  uncorroborated case still runs the full reconcile gate (ADR — the 2-of-3 rule is the safety spine).
- Must NOT reintroduce the "trust fp when dominant" shortcut T-208's "Not" section forbids for the marquee
  cases: the fast-path fires only when the fingerprint's identity **and** the source title agree — the
  Pa Salieu case (fp dominant on the *wrong* recording, title disagrees) still falls through to the gate.
- Engine-touching (changes the land decision path) → same acceptance bar as T-208: re-run the corpus
  compare, prove land/park + tags unchanged except where a corroborated track now lands without the LLM.
