# T-046 — Multi mode: hand-assemble a set of songs into one batch (the dial's third stop, built)

> **Backlog (untriaged).** Filed 2026-08-16 as the deferred half of **ADR-029** (the acquire dial). The
> dial ships in R2 (T-302/T-310) with **Single + Playlist** working and the **Multi** stop present-but-inert
> ("soon"). This ticket **builds** Multi. Owner asked for it while shaping the dial; owner chose to defer the
> build (design-council session, 2026-08-16).

- **Status:** todo — untriaged. Deferred by owner; build after the R2 dial ships.
- **What.** Turning the dial to **Multi** swaps the single paste field for a **keyed stack of single-song
  rows** — each URL inline-validated on paste — with a persistent **"+ add another song"** ghost row at the
  bottom. `Go` is disabled until ≥1 valid row. On submit, the set processes as **one ADR-027 batch**:
  `jobs.playlist_id` set, `youtube_playlist_id` **null** (a manual set, **not** a YouTube playlist), each row
  a member with its `position`. It renders through the **same T-310 aggregate batch card** as a playlist batch.
- **Why it's mostly UI.** The batch data model (ADR-027: `playlists` + membership + `jobs.playlist_id`)
  **already** groups N jobs into one playlist, and ADR-029 already reserves `intent = multi` on the accept
  payload. So this is **input-UI + accept-path wiring**, not a data-model change.
- **Open questions.** Does a manual set get an owner-typed **name** (vs an auto "Untitled set")? Row keying
  must use **stable ids, never array-index keys** (re-order/remove correctness). How does the ambiguity
  confirm (ADR-029) behave if a *playlist* URL is pasted into a Multi row — reject, or offer to expand it into
  rows? Where the "soon" affordance becomes the live stack (same rail slot).
- **Related:** **ADR-029** (the dial + explicit intent), **T-302** (accept path — `intent` reserved),
  **T-310** (the dial screens, incl. the Multi "soon" state this replaces). Not to be confused with **T-045**
  (theme switcher) — different feature, adjacent filing.
- **Done when:** with the dial on Multi, the owner can add N single-song URLs via "+ add another song",
  submit them as one batch that lands under one playlist (pointers to canonical files, `youtube_playlist_id`
  null), and watch it through the one aggregate card — with row add/remove/re-order correct under stable keys.
