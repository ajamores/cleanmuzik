# T-035 — Shazam as a backup fingerprint tier (when AcoustID misses)

> **Backlog (post-R1) · EXPERIMENT IN FLIGHT.** Match-quality, not R1.1 spine — reduces *what lands
> in review*, so it stays out of the R1.1 slice per the scope-triage rule (top of
> `docs/r1/tickets.md`). Triage into a release when acquisition match-rate or **R2/migrate** is
> scoped. See `README.md` for how this directory works.

- **Status:** **GO — ratified as ADR-019 (owner decision, 2026-07-25).** Shazam identified **4 of the 5
  distinct parked tracks**, all clearing MusicBrainz at **score 100** once the title is normalised. The
  decision, its **three** binding conditions (identification-only, fail-soft, and — added 2026-07-27 —
  never-auto-land) and the accepted unofficial-API risk live in **`docs/r1/adr.md` ADR-019** — that is
  the authority; the evidence below is the supporting record. **Still to do: a build ticket for the
  tier.**

- **The idea.** Add a second "identify by sound" tier: **AcoustID miss → Shazam (via
  [`shazamio`](https://github.com/shazamio/ShazamIO)) → returns a clean artist + title → feed the
  existing MusicBrainz search → auto-land (or high-confidence candidate).** Architecturally *cleaner*
  than T-034's title-parsing heuristics: it identifies by the audio, not by un-mangling a dirty
  YouTube string. Shazam's database is consumer-scale — far larger than AcoustID's crowd-sourced
  Chromaprint DB, and strongest on exactly the commercial/label tracks AcoustID tends to miss.

- **Evidence (2026-07-25, the Nipsey track `G3CwMb1IvDU`).** The exact rip AcoustID could **not**
  fingerprint, Shazam identified cold:
  | field | Shazam returned |
  |---|---|
  | title | All Get Right (feat. J. Stone) |
  | artist | Nipsey Hussle |
  | album / year | Crenshaw / 2013 |
  | genre | Hip-Hop/Rap |
  | ISRC | TCABR1336964 |
  - **The ISRC → MB shortcut did NOT work here** — `isrc:TCABR1336964` returns **0** MusicBrainz
    recordings (MB doesn't index it). So do **not** build on ISRC as the bridge.
  - **The reliable bridge is artist + title** — `title:"All Get Right" artist:"Nipsey Hussle"` returns
    a **score-100** MB match (proven earlier this session). Shazam supplies those two fields correctly
    separated, which is the whole problem T-034 was trying to solve by string-parsing.

- **MEASUREMENT (2026-07-25) — the rescue rate over the real parked queue.** The live DB holds **9
  review rows, but only 5 distinct tracks** (the Nines "Franklin" rip is parked 5×). Staging audio had
  already evaporated from `/tmp` (see *Collateral finding*), so all five were re-downloaded from their
  stored YouTube URLs and fed to Shazam cold.

  | # | parked query | Shazam said | MB (normalised) |
  |---|---|---|---|
  | 1 | `Outro` | Nines — Outro *(Crabs in a Bucket, 2020)* | **100** |
  | 2 | `Coming Of Age ft. Memphis Bleek` | JAŸ-Z — Coming Of Age *(Reasonable Doubt, 1996)* | **100** |
  | 3 | `Nines - Outro "Franklin"` ×5 rows | **no match** | — |
  | 4 | `All Get Right ft. J Stone…` | Nipsey Hussle — All Get Right *(Crenshaw, 2013)* | **100** |
  | 5 | `Nipsey Hussle "All Get Right"…` | Nipsey Hussle — All Get Right *(Crenshaw, 2013)* | **100** |

  - **By distinct track: 4/5 rescued (80%). By queue row: 4/9 (44%)** — the gap is entirely the one
    residual having duplicated itself five times. Quote the 80%; the 44% is a duplicate-parking
    artifact, not a Shazam property. **n=5 is a small sample** — this is a strong signal, not a rate.
  - **The miss is the predicted one** and it is not "obscure artist": Shazam nailed Nines' *Outro*
    (row 1) and missed only the `"Franklin"` **music-video edit**. The residual is *this particular
    cut of audio*, which is exactly what the manual escape hatch (T-103) exists for.

- **SIXTH TRACK, tested 2026-07-27 — the failure mode the measurement above never sampled.** The five
  tracks in the table were the nine dead rows. The *tenth* review — **Frank Ocean — Strawberry Swing**,
  the one whose audio survived (now T-103's fixture) — was never fed to Shazam. It was, cold, from
  `/home/armand/cleanmuzik-data/staging/cleanmuzik-5mxn_zm6/WgPXj2fEiW8.mp3`:

  | field | Shazam returned |
  |---|---|
  | title | Strawberry Swing |
  | artist | **Coldplay** |
  | album / year | Viva La Vida or Death and All His Friends / 2008 |
  | label | Parlophone UK |
  | ISRC | GBAYE1600219 |
  | genre | Alternative |

  - **This is not a miss — it is a confident wrong answer**, and that distinction is the whole finding.
    *nostalgia, ULTRA* is sung over the **original instrumentals**; a fingerprint reads the whole mix
    and most of that mix genuinely *is* Coldplay's master. Shazam is working correctly and reporting
    what it heard.
  - **It defeats the fail-soft condition as originally written.** No error, no timeout, no rate-limit,
    no no-match — so nothing parks. `artist:"Coldplay" title:"Strawberry Swing"` scores **100** at MB,
    which is auto-land territory. The tier would have converted a review the system *correctly refused
    to guess at* into a mistagged file. → **ADR-019 condition 3** (a Shazam-derived match may never
    auto-land on its own), added 2026-07-27; the build ticket must carry it.
  - **The class, not the case:** covers, interpolations and mixtape cuts over another artist's master.
    Common in exactly the catalogue this tool is being built for.
  - **Rescue rate is unchanged at 4/5** — this track was never in that denominator. But it means the
    residual is **two** classes now (see the miss note above), and both land on T-103.
  - **Possible bearing on the original T-034 mystery.** Coldplay tops Frank Ocean's live candidate list
    at 0.52 and nobody could explain how. If AcoustID fingerprint-matched the same instrumental, the
    candidates arrive by *sound*, not by title-mangling — which would explain why the title-mangling
    reproduction attempt returned 0 hits. **Hypothesis only**; settling it still needs the actual query
    logged (T-034's instrumentation item).

- **CORRECTION to the "reliable bridge" claim above — it needs one line of normalisation.** Feeding
  Shazam's fields to MB *verbatim* scored **0 hits on 3 of the 4**, which reads as a Shazam failure and
  isn't one. Causes and fixes, both cheap:
  1. **Shazam appends `(feat. X)` to the title; MB keeps featured artists in the credit, not the
     recording title.** Strip a trailing `(feat. …)` / `ft.` and every one of the 4 jumps to **score
     100**. This single regex is the difference between 1/4 and 4/4.
  2. **Shazam uses stylised artist glyphs** (`JAŸ-Z`). ASCII-folding the artist isn't required to get a
     hit — it improves *ranking* (it promoted the better JAY-Z recording from 2nd to 1st).
  3. **Phrase-quoting is load-bearing.** An unquoted `"<title> <artist>"` search returned pure garbage
     for both probes (top hits: *DJ Muggs — "Jay Z"*, *MERO — "Hussle Nipsey"*). Quote the fields.
- **ISRC re-tested — softer than recorded above.** It is not a dead end, just not *the* bridge: it
  missed for Nipsey (0 recordings, as already known) but **hit for JAY-Z**, returning the best result of
  the whole run — the *Reasonable Doubt* recording with the `Jaÿ-Z, Memphis Bleek` credit intact. Cheap
  enough to try first, with artist+title as the reliable fallback.

- **Collateral finding (not about Shazam — now R1.1 `T-106`).** Parked reviews store a `staging_path` under
  `/tmp/cleanmuzik-*`, and **9 of the 10 live reviews point at a directory that no longer exists.** The
  review *row* is durable (T-101/T-104); the audio it points at is not, so those 9 are unresolvable.
  **The 10th is the proof of mechanism:** *Frank Ocean — Strawberry Swing*, parked 2026-07-25 16:39, has
  its audio intact. The only variable is **age** — the retention code works; the OS reaped the older
  dirs out of `/tmp` while they waited. (Corollary for cleanup: it must be **selective** — delete rows
  whose file is missing, never "clear the queue", which would take the healthy one with it.)
  **This is a gap between two decisions, not a decision.** `spec.md:148` is explicit —
  *"a parked song KEEPS its staging file… deleting it makes the resolve unimplementable"* — and the code
  honours it (`run_pipeline`'s `finally` skips the `rmtree` on a park). What was never chosen is *where*:
  `jobs.py:275` uses `mkdtemp(dir=staging_root)` and `staging_root` **defaults to the system temp**, with
  the comment at `jobs.py:272` showing the override was added so *pytest* could clean up — the production
  default was inherited, not decided. So the app retains the file faithfully in a directory the OS is
  entitled to reap. Fix is small (the setting already exists); also constrains **T-103**, whose
  "re-search" exit assumes the audio is still there. Note `_incoming_detail` guards with
  `os.path.isfile` but the resolve path has no equivalent check.

- **How it slots in (keeps the constraints).** Identification only. beets + MusicBrainz stay the
  tagging engine (**ADR-005 intact — not hand-rolled**); Shazam is just a better "what is this?"
  signal that either auto-fills the manual re-search (see T-103 / `docs/r1.1/design/review-rescue-flow.html`)
  or drives the MB search directly.

- **Cautions — weigh before adopting (this is why it's an ADR, not a silent add).**
  1. **Unofficial, reverse-engineered API.** `shazamio` hits Shazam's *private* endpoints — can break
     with no notice, ToS grey area. Low practical risk for a single-user tool; still a dependency that
     can rot.
  2. **It was part of the *abandoned* design.** The old `music-cleaner` / secret-mode PRD used
     ShazamIO **as the engine**; that was dropped for beets + AcoustID. This is a *different* use — a
     backup **identification** tier feeding beets/MB, not the engine — but the door was closed once, so
     re-opening it needs an explicit ADR, not a quiet dependency add.
  3. **Network dependency** — rate limits, latency, a new pipeline failure mode.

- **Relationship to other tickets.**
  - **Likely supersedes T-034's auto-match Layers 0–2** (channel-segment matching, scored inversion
    retry). Shazam is strictly better than parsing reversed titles. T-034's Layer 1 (pure cruft-regex)
    can still stand for R2/migrate.
  - **Does NOT remove the manual escape hatch / keep-untagged (T-103).** Shazam won't know genuinely
    obscure bootlegs (e.g. a random user's TV-audio mix). The tiers **stack**:
    `AcoustID → Shazam → manual re-search → keep-my-tags`. Shazam shrinks the queue; the manual exits
    catch what it also misses.

## Candidate sibling tier — an LLM as the *disambiguator* (raised 2026-07-28, not decided)

**The idea.** When AcoustID misses, hand the LLM the messy YouTube title and let it produce a
**corrected artist/title query** — which MusicBrainz then answers with a real recording. Same shape as
the Shazam tier, different sense organ: Shazam listens, the LLM reads.

**Why it's not redundant with Shazam.** It targets precisely the class ADR-019's condition 3 was added
for. Frank Ocean's *Strawberry Swing* is the fixture: AcoustID silent, Shazam confidently wrong
(*Coldplay, Viva La Vida* — the audio genuinely is mostly Coldplay's instrumental), and yet the string
"Frank Ocean - Strawberry Swing" is trivially disambiguated by anything that knows the catalogue: it's
the *nostalgia, ULTRA* cover, a different recording from the 2008 original. Neither audio-based tier can
hold that knowledge; it isn't in the waveform.

**Two conditions it would inherit, both non-negotiable.**
1. **It never emits an MBID.** Asked for one, an LLM returns a well-formed UUID that does not exist. It
   produces a *query*; MusicBrainz produces the identity. beets still tags (ADR-005 intact).
2. **A vote, not a verdict** — ADR-019 condition 3, unchanged. It populates candidates and can never
   reach the 0.90 auto-accept bar. Its failure mode is the mirror of Shazam's: confident invention on
   genuinely obscure tracks, where Shazam's is confident misattribution on covers.

**Its blind spot, stated plainly.** An uninformative title (`FULL VIDEO HD 2019`) gives it nothing,
while AcoustID and Shazam may still succeed. The tiers are complementary, not competing — which is why
this is an addition to the order, never a replacement for it.

**Why it is NOT being built now (owner call, 2026-07-28).** It automates a gesture that does not exist
yet. T-103's manual re-search *is* this pipeline — corrected query → MB → candidates → resolve — and
building both at once means proving neither. Once T-103 lands, this shrinks from a subsystem to
"auto-fill the search box that already exists". Volume doesn't force the issue either: after Shazam's
measured 4/5 rescue rate the residual class is small in number, high only in kind.

**Sequencing:** after T-103 ships, and after the Shazam tier (item 4 above), which has measurements
behind it where this has only an argument. No ADR until there's data to bind — ADR-019 earned its
status from the rescue-rate table, and this has no equivalent yet.
