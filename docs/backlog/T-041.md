# T-041 — Signal-glow pointermove forces synchronous layout

**Status:** untriaged
**Found:** 2026-08-05 (T-105 code-review, PLAUSIBLE finding #4)

## Problem

`client/src/useSignalGlow.ts` attaches a document-level `pointermove` handler that calls
`getBoundingClientRect()` on the hovered `.signal-glow` element on **every** move, then
writes two custom properties. Reading layout geometry mid-frame forces a synchronous
reflow on a hot path.

With several track cards and inbox rows mounted (all `.signal-glow`), the reflow-per-move
can produce visible cursor-tracking jank on lower-end machines. The rect could be measured
once per element and cached (e.g. on `pointerenter`, or read from `currentTarget` offsets)
rather than on each move.

Cosmetic micro-perf only — no correctness impact. Deferred from T-105 as low priority.

## Done when

The glow no longer calls `getBoundingClientRect()` on every `pointermove`; the rect is
measured on enter (or derived without forcing layout), and the glow still tracks the
cursor correctly across cards and inbox rows.
