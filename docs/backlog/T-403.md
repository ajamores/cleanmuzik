# T-403 — `.lrc` synced-lyrics sidecars (scrolling lyrics in the car)

> **Backlog (untriaged).** Filed 2026-08-23. Observed on the SoulSync trial (`~/github/music-stack`):
> it writes per-track `.lrc` synced-lyrics sidecars, which Navidrome/Symfonium read for **scrolling**
> lyrics. CleanMuzik embeds *unsynced* lyrics via the beets `lyrics` plugin. A `.lrc` sidecar is the
> better carrier for synced lyrics in the Subsonic ecosystem. Part of the **T-40x listening-layer** set.
> Nice-to-have, not on the critical car path.

- **Status:** todo — untriaged. Lowest priority of the T-40x set.
- **The gap.** Embedded USLT lyrics are unsynced (no per-line timestamps) and Symfonium/Navidrome prefer
  a `.lrc` sidecar for the scrolling/karaoke view. CleanMuzik writes no `.lrc`.
- **The shape of a fix.**
  - Fetch synced lyrics (LRCLIB is the usual source — `~/github/muziktest` and SoulSync both use it) and
    write a `.lrc` **beside** each track (same basename), like the `.m3u8` in T-400 — grouping/lyrics on
    disk, tags untouched.
  - Decide interaction with the beets `lyrics` plugin: keep embedded as fallback, or switch to sidecar-only.
  - Touches the R1.6 "Shazam-vs-LRCLIB synced-lyrics decision" already parked on the roadmap — reconcile
    there rather than duplicating it.
- **Related:** **T-400** (same beside-the-track sidecar pattern) · roadmap R1.6 (synced-lyrics decision) ·
  beets `lyrics` plugin (current embedded path). Prior art: SoulSync `.lrc` output; `~/github/muziktest`.
- **Done when:** a landed track has a matching `.lrc` with timestamps that Symfonium/Navidrome render as
  scrolling lyrics; the decision on embedded-vs-sidecar is recorded (likely an R1.6 note, not a new ADR).
